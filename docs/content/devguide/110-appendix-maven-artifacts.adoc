=== Maven Artifacts

GeoWave releases up to 2.0.1 (the Java 8 line) are available on Maven Central. Later releases and snapshots are not published there yet (see <<publishing>> below); until they are, build GeoWave from source and install it to your local Maven repository (see <<015-building.adoc#build-geowave, Building GeoWave>>). Release binaries from 3.0 on will be attached to link:https://github.com/locationtech/geowave/releases[GitHub Releases, window="_blank"].

GeoWave dependencies can be added through a Maven POM file with the following snippet (replacing `${geowave-artifact}` with the desired artifact and `${geowave.version}` with the desired version):

[source, xml]
----
<dependencies>
  <dependency>
    <groupId>org.locationtech.geowave</groupId>
    <artifactId>${geowave-artifact}</artifactId>
    <version>${geowave.version}</version>
  </dependency>
</dependencies>
----

Once snapshots are published, they can be used by adding the following repository to the POM file:

[source, xml]
----
<repository>
  <id>central-snapshots</id>
  <url>https://central.sonatype.com/repository/maven-snapshots/</url>
  <releases>
    <enabled>false</enabled>
  </releases>
  <snapshots>
    <enabled>true</enabled>
  </snapshots>
</repository>
----

[[publishing]]
==== Publishing

GeoWave publishes through the https://central.sonatype.com/[Sonatype Central Portal]. OSSRH (`oss.sonatype.org`) was retired on 30 June 2025, so the older `nexus-staging-maven-plugin` path no longer works.

Publishing is done by the `Publish` workflow, which runs `.utility/publish-artifacts.sh`. That script signs the artifacts with the CI GPG key and runs `./mvnw deploy -Prelease`; the `release` profile activates `central-publishing-maven-plugin`, which uploads a deployment bundle to the Portal and waits for it to be published.

The workflow is currently gated off pending the Eclipse Foundation's approval of the `org.locationtech` namespace on the Portal. It runs only when a committer starts it manually (Run workflow), or on pushes to `master` once the `PUBLISH_ON_MASTER` repository variable is set to `true`. That variable is read by `master` only; the `2.x-jdk8` branch's copy of the workflow reads its own, `PUBLISH_ON_2X_JDK8`, so publishing a 2.x release does not also start publishing from `master`. The same workflow also publishes the documentation to link:https://locationtech.github.io/geowave/[GitHub Pages, window="_blank"].

Two things must be in place for publishing to work:

* The `SONATYPE_USERNAME` and `SONATYPE_PASSWORD` repository secrets must hold a Central Portal *user token*, not the retired OSSRH account. Tokens are generated from the Portal account page.
* The `org.locationtech` namespace must be verified on the Portal for the publishing account. LocationTech namespaces are administered by the Eclipse Foundation rather than by the project, so obtaining publishing rights goes through the EMO.
