=== Maven Artifacts

Both release and snapshot GeoWave artifacts are available on Maven Central.

GeoWave dependencies can be added through a Maven POM file with the following snippet (replacing `${geowave-artifact}` with the desired artifact and `${geowave.version}` with the desired version):

[source, xml]
----
<dependencies>
  <dependency>
    <groupId>org.locationtech.geowave</groupId>
    <artifactId>${geowave-artifact}</artifactId>
    <version>${geowave.version}</version>
  </dependency>
</dependencies>
----

To use GeoWave snapshots the following repository should be added to the POM file:

[source, xml]
----
<repository>
  <id>central-snapshots</id>
  <url>https://central.sonatype.com/repository/maven-snapshots/</url>
  <releases>
    <enabled>false</enabled>
  </releases>
  <snapshots>
    <enabled>true</enabled>
  </snapshots>
</repository>
----
==== Publishing

GeoWave publishes through the https://central.sonatype.com/[Sonatype Central Portal]. OSSRH (`oss.sonatype.org`) was retired on 30 June 2025, so the older `nexus-staging-maven-plugin` path no longer works.

Publishing is done by the `Publish` workflow, which runs `.utility/publish-artifacts.sh`. That script signs the artifacts with the CI GPG key and runs `mvn deploy -Prelease`; the `release` profile activates `central-publishing-maven-plugin`, which uploads a deployment bundle to the Portal and waits for it to be published.

Publishing from `2.x-jdk8` is off by default. On this branch the workflow runs only when a committer starts it manually (Run workflow), or on pushes to `2.x-jdk8` once the `PUBLISH_ON_2X_JDK8` repository variable is set to `true`. `master` reads its own variable, `PUBLISH_ON_MASTER`, so publishing a 2.x release does not also start publishing from `master`.

The credentials are repository secrets that the Eclipse Foundation manages, declared in the LocationTech https://github.com/locationtech/.eclipsefdn[Otterdog configuration]:

* `CENTRAL_SONATYPE_TOKEN_USERNAME` and `CENTRAL_SONATYPE_TOKEN_PASSWORD`, a Central Portal user token for the `org.locationtech` namespace, which the Eclipse Foundation administers.
* `GPG_PRIVATE_KEY`, `GPG_PASSPHRASE_NEW` and `GPG_KEY_ID`, the project's signing key. The workflow imports the key with `actions/setup-java`, and `maven-gpg-plugin` signs with it.
