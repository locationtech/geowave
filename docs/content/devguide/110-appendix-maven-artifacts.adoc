=== Maven Artifacts

Both release and snapshot GeoWave artifacts are available on Maven Central.

GeoWave dependencies can be added through a Maven POM file with the following snippet (replacing `${geowave-artifact}` with the desired artifact and `${geowave.version}` with the desired version):

[source, xml]
----
<dependencies>
  <dependency>
    <groupId>org.locationtech.geowave</groupId>
    <artifactId>${geowave-artifact}</artifactId>
    <version>${geowave.version}</version>
  </dependency>
</dependencies>
----

To use GeoWave snapshots the following repository should be added to the POM file:

[source, xml]
----
<repository>
  <id>central-snapshots</id>
  <url>https://central.sonatype.com/repository/maven-snapshots/</url>
  <releases>
    <enabled>false</enabled>
  </releases>
  <snapshots>
    <enabled>true</enabled>
  </snapshots>
</repository>
----
==== Publishing

GeoWave publishes through the https://central.sonatype.com/[Sonatype Central Portal]. OSSRH (`oss.sonatype.org`) was retired on 30 June 2025, so the older `nexus-staging-maven-plugin` path no longer works.

Publishing happens automatically from the `Publish` workflow on every push to `master`, which runs `.utility/publish-artifacts.sh`. That script signs the artifacts with the CI GPG key and runs `mvn deploy -Prelease`; the `release` profile activates `central-publishing-maven-plugin`, which uploads a deployment bundle to the Portal and waits for it to be published.

Two things must be in place for this to work:

* The `SONATYPE_USERNAME` and `SONATYPE_PASSWORD` repository secrets must hold a Central Portal *user token*, not the retired OSSRH account. Tokens are generated from the Portal account page.
* The `org.locationtech` namespace must be verified on the Portal for the publishing account. LocationTech namespaces are administered by the Eclipse Foundation rather than by the project, so obtaining publishing rights goes through the EMO.
